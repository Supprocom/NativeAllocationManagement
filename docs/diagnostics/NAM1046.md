# NAM1046: Native builder write state requires direct authority

Severity: error. Enabled by default.

## Cause

Stateful builder writes are checked only when the callback and its state are simple
enough to prove. This rule reports a callback that is indirect, capturing,
asynchronous or an iterator; a state value that is copied or used outside a scoped
operation; and a state type that contains a NAM owner, such as a builder, pool or
lease. Owners must not ride along in callback state, because the callback could then
use or release storage it was never lent.

The check is deliberately cautious. A field typed as `object`, `dynamic`, an interface,
a delegate, a pointer or a type parameter also counts, at any depth, because it could
hold an owner.

```csharp
public readonly record struct OwnerState(NativeBuilder<int> Builder, int Value);

OwnerState state = new(builder, 13); // NAM1028: copies the builder owner
builder.Write(1, in state, WriteValue); // NAM1046: the state type holds an owner
```

## Correction

Pass plain application data as `scoped in` state to one static callback or method
group:

```csharp
public readonly record struct WriteState(int Value);

WriteState state = new(11);
builder.Write(1, in state, WriteValue);

static void WriteValue(scoped NativeBuilderWriter<int> writer, scoped in WriteState state)
{
    writer.AsSpan()[0] = state.Value;
    writer.Commit(1);
}
```

## Ownership and memory constraints

This rule uses authenticated NAM symbols and source-visible lifetime proof.
Suppressing it does not make the reported code safe; the runtime still rejects
stale or concurrent use where it can detect it. No automatic code fix applies.
