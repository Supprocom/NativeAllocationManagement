# NAM1048: Concurrent lease state cannot contain native ownership

Severity: error. Enabled by default.

## Cause

State passed to a concurrent lease's `Process` call must not contain a NAM owner,
directly or inside nested structs or tuples: no pools, arenas, builders, leases or
transfers. A callback that receives an owner could rent, return or release storage
while the lease is being processed.

The check is deliberately cautious. A field typed as `object`, `dynamic`, an interface,
a delegate, a pointer or a type parameter also counts, at any depth, because it could
hold an owner.

```csharp
public readonly record struct PoolState(NativeConcurrentPool<int> Pool);

PoolState state = new(pool); // NAM1001: aliases the pool owner
int first = values.Process(1, in state, static (view, _) => view[0]); // NAM1048
```

## Correction

Pass only application data. Keep owners in the code that owns them, and do any
renting or returning outside the callback:

```csharp
public readonly record struct ProcessState(int Offset);

ProcessState state = new(3);
int total = values.Process(1, in state, static (view, current) => view[0] + current.Offset);
```

## Ownership and memory constraints

This rule uses authenticated NAM symbols and source-visible lifetime proof.
Suppressing it does not make the reported code safe; the runtime still rejects
stale or concurrent use where it can detect it. No automatic code fix applies.
