# NAM1042: Native builder write authority must remain direct

Severity: error. Enabled by default.

## Cause

The writer passed to a `NativeBuilder<T>.Write` callback carries the right to commit
the written range, and it must commit exactly once. The analyzer can only check that
when the writer stays with the callback it was given to. This rule reports a writer
copied to another local, passed to a helper by value, or a callback that reaches
`Write` indirectly, for example through a stored delegate.

```csharp
builder.Write(1, static writer =>
{
    NativeBuilderWriter<int> alias = writer; // NAM1042: a second handle to the writer
    alias.Commit(0);
});

NativeBuilderWriteAction<int> stored = static writer => writer.Commit(0);
builder.Write(1, stored); // NAM1042: the callback is not passed directly
```

## Correction

Pass a lambda or method group directly to `Write`. Forward the writer to helpers
only as a `scoped ref NativeBuilderWriter<T>` parameter whose source the analyzer can
see:

```csharp
builder.Write(4_096, static writer => WriteWords(ref writer));

static void WriteWords(scoped ref NativeBuilderWriter<uint> writer)
{
    Span<uint> values = writer.AsSpan();
    for (int index = 0; index < values.Length; index++)
    {
        values[index] = (uint)index;
    }

    writer.Commit(values.Length);
}
```

## Ownership and memory constraints

This rule uses authenticated NAM symbols and source-visible lifetime proof.
Suppressing it does not make the reported code safe; the runtime still rejects
stale or concurrent use where it can detect it. No automatic code fix applies.
