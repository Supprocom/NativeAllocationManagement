# NAM1041: Native builder write view cannot escape

Severity: error. Enabled by default.

## Cause

Inside a `NativeBuilder<T>.Write` callback, `writer.AsSpan()` points into the
builder's unfinished native storage. That storage can move when the builder grows and
is freed when the builder is disposed, so the span must not leave the callback. This
rule reports a write view that is passed to an ordinary method, stored, returned or
captured.

```csharp
builder.Write(2, static writer =>
{
    Retain(writer.AsSpan()); // NAM1041: the span leaves the callback
    writer.Commit(2);
});

static void Retain(Span<int> values) => _ = values.Length;
```

## Correction

Write through the span inside the callback. To move the writing code into a helper,
pass the writer itself as a `scoped ref NativeBuilderWriter<T>` parameter and take the
span there:

```csharp
builder.Write(4_096, static writer => WriteWords(ref writer));

static void WriteWords(scoped ref NativeBuilderWriter<uint> writer)
{
    Span<uint> values = writer.AsSpan();
    for (int index = 0; index < values.Length; index++)
    {
        values[index] = (uint)index;
    }

    writer.Commit(values.Length);
}
```

## Ownership and memory constraints

This rule uses authenticated NAM symbols and source-visible lifetime proof.
Suppressing it does not make the reported code safe; the runtime still rejects
stale or concurrent use where it can detect it. No automatic code fix applies.
