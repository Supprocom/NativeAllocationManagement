# NAM1050: prepared lease requires a successful acquisition guard

Severity: error. Applies only to the authenticated NAM `NativePool<T>.TryRent`,
`NativeArena.TryScratch`, `NativeArena.TryScratchScoped` and prepared
`NativeLeaseOperations.TryInitializeScoped` ownership-producing
APIs; a same-named external method does not establish proof.

These APIs can return a default capability when their prepared capacity is full.
A default output is not initialized ownership. Borrowing or disposing it without
proving successful acquisition is invalid even though its C# type is a lease.

```csharp
// Invalid: the result is ignored.
pool.TryRent(4, static writer => writer.Fill(42), out Pooled<int> lease, out _);
lease.Dispose();
```

Guard the actual acquisition and complete the successful lifetime on every path:

```csharp
if (pool.TryRent(4, static writer => writer.Fill(42), out Pooled<int> lease, out _))
{
    try
    {
        _ = lease.Read(static view => view[0]);
    }
    finally
    {
        lease.Dispose();
    }
}
```

A direct negated early-return guard is also supported. Named argument ordering
does not change ownership proof. A false acquisition branch cannot use its
default output and receives the existing inactive-handle diagnostic. Missing
successful-path cleanup remains NAM1003. Short-circuit conditions must not hide
an acquired lease on paths where a later condition is false.

The analyzer is deliberately conservative when a result is ignored or separated
from an authenticated direct guard. It does not infer success from capacity
estimates, an unrelated/reassigned boolean or a lookalike call. Runtime guards
remain effective with analyzer diagnostics suppressed. There is no automatic
code fix for choosing the application's capacity-failure path.

See [prepared fixed-shape pools](../prepared-pools.md) for expected exhaustion,
initialization failures, retention and memory accounting. Prepared arena outputs
use the same actual success-branch proof, but their common lifetime ends through
the arena's existing reset, scoped recycle or disposal boundary. See
[prepared arenas](../prepared-arenas.md) for their byte-bound contract.
Prepared groups gate every output on the same successful result and require
complete lexical scoped-batch cleanup, not independent disposal of each range.
See [fast mapped/group operations](../fast-arena-integration.md).
