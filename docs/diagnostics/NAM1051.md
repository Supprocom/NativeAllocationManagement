# NAM1051: Lease span is used after its storage ended

Severity: error. Enabled by default.

## Cause

`AsSpan()` checks the lease once and returns a plain `Span<T>` over its native
storage. The span carries no ownership, so it does not know when that storage is
returned or reused. This rule reports a span, or a slice of one, used after the
lease was disposed or moved, after its arena was reset, scoped-recycled or disposed,
or after the end of its region's `using` block.

```csharp
Pooled<int> lease = pool.Rent(4, 0);
Span<int> values = lease.AsSpan();
lease.Dispose();
values[0] = 1; // NAM1051: the storage went back to the pool
```

## Correction

Finish using the span before the lease ends. If you need the storage again, take a
new span from a current lease:

```csharp
using Pooled<int> lease = pool.Rent(4, 0);
Span<int> values = lease.AsSpan();
values[0] = 1;
```

## What the compiler rejects

The span is bound to the variable that holds the lease, so the C# compiler refuses
to let it leave that variable's scope:

```csharp
static Span<int> First(NativePool<int> pool)
{
    using Pooled<int> lease = pool.Rent(4, 0);
    return lease.AsSpan(); // CS8168: the span would outlive the lease
}
```

The same holds for storing the span in a ref struct passed in by `ref`, assigning it
to an `out Span<T>`, and keeping it after the block that declares the lease. A
`Local<T>` is bound to its `NativeRegion` the same way. Return the lease to a caller
that owns it, or copy the values out.

One declaration needs care. A local initialized with `default` is treated as
reaching the whole method, so assigning a lease span to it later fails. Mark it
`scoped`:

```csharp
Span<int> values = default;          // WRONG: CS8168 on the next line
values = lease.AsSpan();

scoped Span<int> values = default;   // right
values = lease.AsSpan();
```

A helper that returns a span from a lease takes the lease as `in` or `ref`, not by
value. This rule covers what the compiler cannot see: using the span again in the
same method after the storage ended.

## Ownership and memory constraints

This rule uses authenticated NAM symbols and source-visible lifetime proof.
Suppressing it does not make the reported code safe; the runtime still rejects
stale or concurrent use where it can detect it. No automatic code fix applies.
