# NAM1051: Lease span is used after its storage ended

Severity: error. Enabled by default.

## Cause

`AsSpan()` checks the lease once and returns a plain `Span<T>` over its native
storage. The span carries no ownership, so it does not know when that storage is
returned or reused. This rule reports a span, or a slice of one, used after the
lease was disposed or moved, after its arena was reset, scoped-recycled or disposed,
or after the end of its region's `using` block.

```csharp
Pooled<int> lease = pool.Rent(4, 0);
Span<int> values = lease.AsSpan();
lease.Dispose();
values[0] = 1; // NAM1051: the storage went back to the pool
```

## Correction

Finish using the span before the lease ends. If you need the storage again, take a
new span from a current lease:

```csharp
using Pooled<int> lease = pool.Rent(4, 0);
Span<int> values = lease.AsSpan();
values[0] = 1;
```

The C# compiler already keeps a lease span inside the method that holds the lease.
This rule covers what the compiler cannot see: using the span again in that method
after the storage ended.

## Ownership and memory constraints

This rule uses authenticated NAM symbols and source-visible lifetime proof.
Suppressing it does not make the reported code safe; the runtime still rejects
stale or concurrent use where it can detect it. No automatic code fix applies.
